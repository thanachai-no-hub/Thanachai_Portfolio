Backend · healthcare API

Agnos Hospital Middleware

A Go service that lets hospital staff log in and search the patients of their own hospital. When a patient is not in the local database yet, it fetches the record from the hospital's information system (HIS), caches it, and keeps answering even when the HIS is down.

  • Go + Gin in clean layers (handler → service → repository) with GORM on PostgreSQL 16.
  • Staff accounts with bcrypt passwords and HS256 JWT. The hospital comes from the token, never the request body, so staff cannot read another hospital's patients.
  • Search by national ID, passport, Thai or English name, date of birth, phone or email. An ID that misses locally falls through to the HIS, gets cached, and the full filter runs again.
  • Docker Compose with Nginx in front (rate limit on login), PostgreSQL and a mock HIS, plus OpenAPI docs at /swagger.
  • 50 unit tests with in-memory fakes and httptest servers, no database needed: 94–100% coverage on handler, service, auth and HIS client.

    Project detailsWhat it does, highlights and what's under the hood
    What it does
    • Staff are created per hospital (username, password, hospital code) and log in to get a JWT that expires after 24 hours.
    • With that token they search patients of their own hospital, combining any of 8 fields with AND. An empty search lists the hospital's patients, up to 100.
    • If a national ID or passport is not found locally, the service calls that hospital's HIS, stores the patient, then answers.
    • Each hospital keeps its own HIS address in the database, so a new hospital needs no code change.
    Highlights
    • Tenant isolation at the data layer: every query starts with the hospital ID taken from the signed token.
    • One generic login error for unknown hospital, unknown user or wrong password, so usernames cannot be probed.
    • Search is a POST with a JSON body, so national IDs and names never land in URLs or access logs.
    • HIS outage degrades gracefully: the failure is logged as a warning and search still answers with local data.
    • HIS results are upserted on (hospital, HN), then the full filter runs again so the other criteria still apply.
    • Nginx rate limits /staff/* to 5 requests a second (burst 10) against brute-force login. Only Nginx is exposed; the app and database stay on an internal network.
    Under the hood
    • Go 1.26, Gin, GORM, PostgreSQL 16, golang-jwt, bcrypt, slog structured logging, graceful shutdown.
    • Partial indexes on national ID and passport, a unique (hospital, HN) key and a gender check constraint.
    • Multi-stage Dockerfile building a small non-root image for the server and the mock HIS.
    • Repositories and the HIS client are interfaces, so services and handlers are tested with in-memory fakes and httptest servers.
